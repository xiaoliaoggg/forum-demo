giscus 是怎么把评论存进 Discussions 的

2026-11-17·技术·3 分钟阅读

页面上只加了一段 <script>，评论区就出现了。中间其实发生了这么几件事。

1. iframe 加载

client.js 读取 data-repo、data-repo-id、data-category-id，然后往页面里注入一个指向 giscus.app 的 iframe。真正的 UI 和逻辑都在 iframe 里，和你的站点隔离，所以不用担心样式冲突。

2. 定位 discussion

giscus 用 data-mapping 决定“这篇页面”对应哪个 discussion：

  • pathname：用页面路径，推荐，改标题不会丢评论
  • url：用完整 URL
  • title：用页面标题
  • og:title / specific：自定义

找不到对应 discussion 时，它会用 GitHub App 的权限自动新建一个，标题就是页面标题。

3. 登录与写入

用户点“登录”会走 GitHub OAuth，授权给 giscus App。之后的评论、回复、reaction 都通过 GitHub GraphQL API 写进 Discussions，而不是写进某个第三方数据库。

4. 数据归属

这一点很重要：评论数据在你自己仓库的 Discussions 里。你可以用 GitHub 搜索、用 API 导出、迁移到别处，不会被某个评论服务商锁死。

代价是：访客必须有 GitHub 账号。这是所有 GitHub 系评论方案共同的硬限制。
